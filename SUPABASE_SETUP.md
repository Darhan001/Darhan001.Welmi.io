# Supabase setup для каталога Welmi

Этот SQL добавляет новые таблицы каталога, избранного и дневниковых записей. Он не удаляет и не меняет существующие таблицы приложения.

## Как выполнить SQL

1. Откройте нужный проект на [supabase.com/dashboard](https://supabase.com/dashboard).
2. Выберите **SQL Editor** → **New query**.
3. Откройте `SUPABASE_SETUP.sql`, вставьте весь файл и сначала просмотрите его.
4. Нажмите **Run**. Убедитесь, что запрос завершился без ошибок и новые таблицы видны в **Table Editor**.

## Storage

Фото рецептов в начальной версии подгружаются по URL; загрузка файлов в Storage приложением не выполняется. Если решите хранить собственные изображения:

1. Создайте bucket `recipe-images` с публичным чтением.
2. Разрешите `SELECT` для `anon` и `authenticated` на `storage.objects` только для `bucket_id = 'recipe-images'`.
3. Загрузку и удаление оставьте только доверенным администраторам через Dashboard. Не размещайте service role key в приложении.
4. Заполните `recipes.image_url` публичными URL объектов. При ошибке сети приложение показывает placeholder.

## Authentication

- Проверьте, что включены нужные проекту способы входа и корректно настроены redirect URLs.
- Для пользовательских таблиц используется `auth.uid()`. Проверяйте работу RLS под обычной пользовательской сессией.
- Не отключайте RLS и не используйте service role key в Dart-коде.

## Что уже сделано во Flutter

- Существующий экран плана питания заменён каталогом с поиском по названию, категории, тегам и ингредиентам, подборками категорий, фильтрами и ленивой сеткой.
- Есть локальный каталог из 27 рецептов; каждая запись хранит ингредиенты, шаги, КБЖУ и собственную фотографию этого блюда (`idMeal` TheMealDB + файл `assets/images/recipes/<idMeal>_<slug>.jpg`).
- Репозиторий пробует загрузить опубликованные рецепты из Supabase и при недоступной схеме использует seed-данные. Для рецептов, которые уже есть в проверенном локальном каталоге (совпадение по названию), побеждает локальная запись — так устаревший `image_url` в базе не вернёт чужое фото. Дополнительные рецепты из базы добавляются к каталогу.
- Избранное хранится для текущего пользователя в локальном кэше и синхронизируется с таблицей `recipe_favorites`, когда SQL выполнен.
- Добавление рецепта использует уже существующие `food_entries`, `meal_items` и `DailyTracker`, чтобы запись немедленно появилась в текущем дневнике и обновила калории/БЖУ.
- В `meal_entries` заложена нормализованная схема на будущее; текущий UI пока сохраняет в существующие таблицы, чтобы не дублировать дневник.
- Все SQL политики включают RLS: чтение опубликованных рецептов открыто, избранное и `meal_entries` принадлежат только владельцу.

## Что нужно сделать вручную

- Выполнить `SUPABASE_SETUP.sql` в проекте Supabase.
- Наполнить таблицы `recipe_categories`, `recipes`, `recipe_ingredients` и `recipe_steps`. Встроенный seed работает локально, но автоматически не загружается в Supabase.
- При использовании собственных фотографий создать bucket и политики Storage по инструкции выше.
- Проверить провайдеры Authentication и redirect URLs для ваших платформ.
- Добавить ключ поддерживаемого AI-провайдера в конфигурацию приложения, чтобы работали транскрибация и AI-анализ голосового ввода, а также вопросы по рецептам. Ключ остаётся в локальной конфигурации/секретах сборки, не в SQL и не в исходниках.

## Оставшиеся ограничения

- Голосовой ввод зависит от настроенного API-ключа для транскрибации и AI-анализа. До подтверждения на экране результат в дневник не записывается.
- Seed-фотографии упакованы в приложение (`assets/images/recipes/`) и не требуют интернета; `strMealThumb` используется только как резерв, а при ошибке показывается нейтральный placeholder, никогда — фото другого блюда.
- Для собственных рецептов в Supabase указывайте публичный `image_url`: локальные пути из старых данных могут уже не существовать.
- Seed-данные содержат начальные приблизительные нутриенты; перед production их следует проверить специалистом и загрузить утверждённый каталог в Supabase.
