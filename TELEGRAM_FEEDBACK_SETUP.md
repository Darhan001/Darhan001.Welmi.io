# Настройка обратной связи Welmi → Telegram

Flutter вызывает функцию `send-feedback` через уже настроенный Supabase client. Функция проверяет категорию и размер сообщения, сверяет `user_id` с сессией Supabase и отправляет сообщение через официальный Telegram Bot API. Для гостевой сессии `user_id` должен быть пустым; сервер покажет отправителя как «Гость». `chat_id` из тела запроса не принимается и всегда берётся только из секрета `TELEGRAM_CHAT_ID`.

## 1. Добавьте секреты в Supabase

1. Откройте нужный проект в [Supabase Dashboard](https://supabase.com/dashboard).
2. Перейдите в **Edge Functions → Secrets** (в некоторых вариантах панели раздел называется **Edge Function Secrets**).
3. Создайте секрет TELEGRAM_BOT_TOKEN и вставьте значение только в поле секрета.
   4. Создайте секрет TELEGRAM_CHAT_ID и вставьте ID чата только в поле секрета.
5. Сохраните значения. Не вставляйте их в исходники, Flutter `--dart-define`, Git, локальные `.env`/`env.json`, логи или этот документ.

Создавать эти secrets может владелец/администратор проекта. Supabase предоставляет secrets как переменные окружения Edge Functions.

## 2. Получите Chat ID и подготовьте бота

Для личного чата можно узнать собственный числовой Telegram ID у `@userinfobot`. Откройте именно вашего бота и отправьте ему `/start`, чтобы он мог написать вам первым. Значение ID сохраните в Supabase как `TELEGRAM_CHAT_ID`.

Для группы добавьте бота в нужную группу и получите ID чата группы через используемый вами доверенный способ просмотра Telegram update. Для групп ID обычно отрицательный. Не публикуйте bot token в чатах, тикетах или скриншотах. Если токен случайно раскрыт, отзовите его у `@BotFather` и замените secret в Supabase.

## 3. Задеплойте функцию

В проекте опубликована настройка `supabase/config.toml`: у функции выключена встроенная JWT-проверка gateway, чтобы гостевой вызов работал и при новом формате publishable key. Внутри функции проверяется ключ текущего Supabase проекта, а токен авторизованного пользователя отдельно проверяется через Supabase Auth. Не удаляйте эту проверку из кода и не выключайте проверку пользовательского токена.

Из корня проекта, где уже настроен Supabase CLI и выполнен `supabase link` для нужного проекта, выполните:

```text
supabase functions deploy send-feedback
```

Либо создайте/обновите Edge Function `send-feedback` через редактор Edge Functions в Dashboard, скопировав код из `supabase/functions/send-feedback/index.ts`, и нажмите Deploy. Если разворачиваете вручную в Dashboard, задайте функции `verify_jwt = false` согласно `supabase/config.toml`; функцию нужно деплоить вместе с этой настройкой. Дополнительная таблица и миграция для доставки в Telegram не нужны; существующая локальная история отправленных сообщений остаётся локальной.

## 4. Проверьте доставку

1. Убедитесь, что оба secrets заданы без пробелов в начале/конце.
2. Проверьте, что пользователь открыл чат с ботом и отправил `/start` (для личной доставки).
3. Запустите Welmi с корректной существующей конфигурацией Supabase.
4. Откройте **Обратная связь**, выберите категорию, введите непустое сообщение и нажмите **Отправить**.
5. При успехе приложение покажет существующее подтверждение и очистит поле. При ошибке текст останется в форме для повторной отправки.
6. Если сообщение не пришло, посмотрите выполнение функции в Supabase **Edge Functions → Logs**. Диагностика показывает `request received`, статусы `SECRET EXISTS/MISSING`, начало вызова Telegram и его HTTP/error code. Код не пишет токен, chat ID или тело сообщения в логи.

Функция принимает только категории `feedback`, `bug`, `idea`, `support` и текст длиной до 3000 символов. Telegram недоступен или возвращает ошибку — функция вернёт ошибку доставки, а приложение покажет сообщение с возможностью повторить отправку.
