# Welmi — аудит безопасности

Дата: 15.11.2026. Ветка `refactor/welmi-transformation`.

Проверялся код клиента (`lib/`), Edge Functions (`supabase/functions/`), SQL в репозитории,
манифесты Android/iOS и конфигурация сборки. **Рабочая база Supabase не проверялась** — доступа
к ней из репозитория нет, поэтому всё, что касается реальных политик RLS и бакетов Storage,
помечено как «проверить вручную». Этот документ не гарантирует безопасность приложения.

Обозначения: 🔴 требует действия владельца · 🟡 риск принят или частично закрыт · 🟢 в порядке / исправлено.

## 2. Журналы и сообщения об ошибках

| # | Что | Статус |
|---|-----|--------|
| 2.1 | В коде 160 вызовов `debugPrint`, многие печатают текст исключения (`$e`). В release `debugPrint` по умолчанию **продолжает писать в logcat**, а там бывают id пользователя и ответы сервера. **Исправлено:** `silenceLogsInRelease()` в `lib/app/bootstrap.dart` отключает вывод в release; покрыто тестом. | 🟢 |
| 2.2 | Ключ Gemini передаётся заголовком `x-goog-api-key`, а не в URL — не попадает в текст сетевых исключений. | 🟢 |
| 2.3 | Пользователю не показывается сырой текст исключений: ошибки Open Food Facts, подписки, AI, голоса — типизированные коды, текст строится из локализации. | 🟢 |
| 2.4 | Edge Functions не логируют токены и тела запросов; `send-feedback` логирует только факт наличия секретов. | 🟢 |

## 3. Supabase: авторизация и изоляция данных

Клиент обращается к таблицам `profiles`, `food_entries`, `meal_items`, `water_entries`,
`weight_entries`, `device_tokens`, `recipes`, `recipe_favorites`, `subscription_entitlements`
и бакету `avatars`. Клиентские запросы фильтруют по `user_id`, но это **не защита** — защищает только RLS.

| # | Что | Статус |
|---|-----|--------|
| 3.1 | В SQL-файлах репозитория RLS включается для всех перечисленных таблиц. Но основные таблицы описаны в `supabase_schema.sql` / `SUPABASE_SETUP.sql` в корне, а не в `supabase/migrations/` — нет гарантии, что рабочая база совпадает с файлами. | 🔴 проверить |
| 3.2 | Для проверки есть готовый скрипт только на чтение: `supabase/audit/rls_audit.sql`. Запустите его в SQL Editor и убедитесь, что у каждой таблицы `rowsecurity = true` и политики ограничивают по `auth.uid()`. | 🔴 проверить |
| 3.3 | Бакет `avatars`: политик Storage в репозитории нет. Клиент пишет в `<userId>/<timestamp>.<ext>` и берёт публичный URL. Нужна политика «писать только в папку со своим `auth.uid()`»; иначе любой вошедший может перезаписать чужой аватар. | 🔴 проверить |
| 3.4 | Аватары публичны по ссылке (это осознанно: URL хранится в профиле). Старые файлы при смене аватара не удаляются — хранилище растёт. | 🟡 |
| 3.5 | Premium определяется только серверной таблицей `subscription_entitlements`; клиент в неё не пишет. `verify-subscription` проверяет сессию, список продуктов и привязку покупки к аккаунту. | 🟢 |
| 3.6 | `send-push`: отправка только себе либо по service-role ключу (сравнение с самим ключом, а не чтение роли из неподписанного JWT). `send-reminders`: только планировщик (service-role или `CRON_SECRET` ≥ 16 символов). | 🟢 |
| 3.7 | `send-feedback` и `store-notifications` работают с `verify_jwt = false` и аутентифицируют вызов сами (публичный ключ проекта + сессия; OIDC Google / JWS Apple). У `send-feedback` нет ограничения частоты — гостевой вызов можно использовать для спама в Telegram-чат поддержки. | 🟡 |
| 3.8 | Миграция `202609300001_subscription_entitlements.sql` помечена как предложение и к базе не применялась. Без неё Premium не работает. Применять только после вашей проверки. | 🔴 |

## 4. Локальное хранение

| # | Что | Статус |
|---|-----|--------|
| 4.1 | Сессию Supabase хранит `supabase_flutter` (SharedPreferences). Это стандартное поведение пакета; для повышенных требований можно подключить `flutter_secure_storage` как `localStorage`. | 🟡 |
| 4.2 | В SharedPreferences лежат настройки, кэш дня и очередь несинхронизированных записей (вода и т.п.) — данные о здоровье в открытом виде в песочнице приложения. На устройстве без root недоступны другим приложениям. | 🟡 |
| 4.3 | Блокировка по отпечатку (`local_auth`) — защита экрана, а не шифрование данных. | 🟡 |

## 6. Android

| # | Что | Статус |
|---|-----|--------|
| 6.1 | `applicationId = "com.example.lumina"`. Google Play не принимает `com.example.*`. Смена id затрагивает Firebase, покупки и OAuth-редирект — решение за вами, до первой публикации. | 🔴 |
| 6.2 | Без `android/key.properties` release подписывается **debug-ключом**. Такой APK годится только для проверки. `key.properties`, `*.jks`, `*.keystore` в `.gitignore`. | 🔴 |
| 6.3 | Разрешения минимальны: нет доступа к медиатеке и геолокации; Health Connect — только чтение четырёх типов. `SCHEDULE_EXACT_ALARM` потребует обоснования в Play Console. | 🟡 |
| 6.4 | R8 и сжатие ресурсов включены; экспортируемые компоненты — только лаунчер, алиас Health Connect (защищён разрешением) и виджет. | 🟢 |
| 6.5 | Плагин `google-services` отключён (нет `google-services.json`), поэтому FCM на Android сейчас не инициализируется — серверные push не доходят, работают только локальные напоминания. | 🟡 |
| 6.6 | Резервное копирование Android (`allowBackup`) не отключено: SharedPreferences с сессией могут попасть в облачную копию устройства. Рассмотрите `android:allowBackup="false"` или правила исключения. Не менял: это влияет на перенос данных пользователя между устройствами. | 🟡 |
